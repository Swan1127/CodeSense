# CodeSense 三阶段引导式学习论文设计

## 一、写作目标

先完成一篇事实完整、方法谨慎的中文研究稿，再据此改写英文投稿版。论文以三阶段引导式学习的设计、真实课堂部署和学习行为分析为主线，不把现有数据表述为教学效果对照实验。

中文工作题目：

> 面向程序设计学习的三阶段引导式学习设计与课堂应用：基于真实在线平台的学习行为分析

英文工作题目：

> Designing Three-Stage Guided Learning for Programming Education: Learning Analytics from a Real-World Classroom Deployment

## 二、研究定位

研究采用设计型研究与回顾性学习分析相结合的思路。论文说明三阶段学习流程的设计依据，重建系统在课堂部署期间的迭代过程，并利用平台日志分析学生的采用、持续使用、阶段推进和退出情况。代码提交表现仅用于探索性关联分析，不作因果解释。

这一路线适合当前数据条件：

- 平台保留了会话、阶段事件和代码提交数据，可以分析真实使用过程；
- 学生自行选择是否进入引导式学习，没有随机分组或预先设置的对照组；
- 引导式学习参与与课程设计过程分存在低门槛联系；
- 系统在采集期间持续更新，第二阶段发生过实质改版；
- 代码提交通过率较高，存在明显的结果指标天花板效应。

## 三、核心贡献

1. 提出“思路外化—代码重构—角色反转教学”的三阶段程序设计学习流程。
2. 将算法解释、程序重构、learning-by-teaching 和错误代码修正组织为连续学习任务，并记录细粒度阶段事件。
3. 报告该流程在两个自然班课程设计中的真实部署情况，包括492次引导式学习会话和9940条阶段日志。
4. 结合 Git 历史和平台时间戳重建系统版本，区分先导、过渡和稳定阶段，降低版本混合对结果解释的影响。
5. 在没有对照实验的条件下，提供学生采用、重复使用、阶段漏斗和代码提交表现的探索性证据，并如实讨论自选择、课程激励和系统迭代等限制。

论文不将三阶段设计的单个组成部分宣称为全新方法。创新点放在流程组合、双角色费曼教学、错误代码修正闭环、细粒度过程记录及真实课堂迭代分析上。

## 四、研究问题

### RQ1 学生采用与持续使用

学生如何进入和持续使用三阶段引导式学习？

主要指标包括参与人数、会话数、重复使用比例、跨作业使用、每名学生会话分布和使用集中度。

### RQ2 阶段推进与退出

学生在三个学习阶段中的推进、停留和退出呈现什么特征？

主要指标包括阶段到达率、阶段通过率、完整完成率、提示请求、对话轮次、事件间隔和退出位置。

### RQ3 版本迭代与使用轨迹

平台迭代前后，学生的参与和完成轨迹有何描述性差异？

该问题只报告版本期间的会话量、事件量、阶段到达和完成轨迹，不把版本差异解释为教学效果。早期版本样本较小，学生和作业也不独立，不能进行简单显著性比较。

### RQ4 与代码提交表现的探索性关联

引导式学习参与程度与后续代码提交表现存在怎样的探索性关联？

结果指标包括最终是否完全通过、最终沙箱测试通过率和提交尝试次数。模型结果用于描述条件关联，不用于证明三阶段学习改善了编程成绩。

## 五、三阶段学习设计

### 5.1 第一阶段：思路外化

学生在编写代码前回答有关输入、核心步骤、边界条件和输出的问题。系统根据预设的关键步骤提供反馈和提示，达到后台判定阈值后进入第二阶段。

第一阶段在部署期间发生过调整：

- 初始版本要求学生在一个文本框中描述完整思路；
- 2026年6月24日加入算法简述和引导问题，后台通过阈值由80分降至50分；
- 2026年6月25日改为按问题分别填写，并限制直接粘贴。

曾有一段时间前端提示显示60分，而后台实际通过条件是50分。论文以后台记录为准，并在局限或数据处理说明中披露该差异。

### 5.2 第二阶段：代码重构

第二阶段要求学生把第一阶段形成的算法思路映射到程序结构。该阶段有两个不同版本：

- 2026年6月26日以前使用代码块选择、排序、缩进调整和干扰块识别，接近 Parsons Problems；
- 2026年6月26日起改为逐步选择和填空，并同步显示代码预览。

正文统一使用“代码重构阶段”这一上位名称。只有描述早期版本时使用“Parsons型代码块重构”，避免把全部会话错误归类为 Parsons Problems。

### 5.3 第三阶段：角色反转教学

学生先与教师智能体对话，澄清仍不理解的知识点；随后向一个基础较弱的虚拟学生讲解解题过程。虚拟学生根据对话生成一份带有典型错误的代码，学生检查并修正，系统再判断修正结果。

第三阶段的基本教学逻辑在研究期间保持稳定。后续更新主要增加历史状态恢复、重复回答拦截、题目上下文和学生当前状态注入，改善了交互连续性。

## 六、教学场景与参与方式

研究场景为沈阳航空航天大学2024级网络工程1、2班的数据结构课程设计。学生既可以直接编写代码，也可以从作业页面进入三阶段引导式学习。教师在班级群中鼓励学生尝试使用系统，但没有要求每道题必须使用。

课程设计成绩中有10分与学习过程参与有关。实际执行采用低门槛、宽松评分：学生尝试使用即可获得大部分分数，多数得到8—9分；完全没有参与的学生可能得到0分，但不会仅因该项成绩不及格。

论文将这种参与方式描述为：

> 学生可自主选择是否进入引导式学习，但参与行为受到低门槛课程过程分的鼓励。

不得使用“完全自愿参与”“无任何成绩影响”或“强制使用”等不符合实际情况的表述。

## 七、数据范围与分析样本

线上导出数据包括：

- 123个用户账户，其中117个学生账户；
- 85项作业；
- 1858次代码提交；
- 492次引导式学习会话；
- 9940条阶段事件日志；
- 85条引导式学习预设记录。

实际进入过引导式学习的学生有42人，其中34人至少完成过一次完整流程。

分析分为三个口径：

### 7.1 全量部署样本

全部492次会话用于分析总体采用、重复使用、跨作业使用和全周期行为分布。

### 7.2 稳定版本主样本

以2026年6月28日00:26（北京时间）附近的 Git 提交作为稳定版本边界。该边界之后建立了398次会话，涉及40名学生，其中224次完成。稳定版本样本用于主要阶段漏斗和行为分析。

### 7.3 版本与敏感性样本

早期31次会话用于描述先导部署和设计迭代，63次测验版过渡期会话单独报告。跨版本边界的会话进行标记，并在敏感性分析中排除。

数据库时间戳表现为 UTC，Git 提交时间为北京时间。分析时统一转换时区。线上平台通常在主分支推送后立即更新，因此 Git 提交时间可以近似视为版本切换时间，但仍保留分钟级部署延迟的不确定性。

## 九、分析方法

### 9.1 RQ1

进行学生级和会话级描述统计。报告使用人数、会话分布、重复使用、跨作业使用以及高频用户对总会话量的贡献。用中位数和四分位距描述偏态分布。

### 9.2 RQ2

根据阶段日志重建“开始第一阶段—通过第一阶段—通过第二阶段—完成第三阶段”的漏斗。活跃时间以相邻事件间隔截断法估计，避免把页面长时间闲置计入学习时间。完成和未完成会话分别报告。

### 9.3 RQ3

按照 Git 版本边界统计会话、用户、作业、事件和阶段通过情况。版本结果仅作描述性比较。对跨边界会话分别采用保留、按事件时间拆分和排除三种处理，检查结论是否改变。

### 9.4 RQ4

以“学生—作业”为分析单位，建立引导式学习记录与代码提交记录的时间关系。主要比较：

- 首次代码提交前是否使用过引导式学习；
- 是否完成完整三阶段；
- 引导式学习会话数和阶段到达深度。

结果指标为最终是否完全通过、最终沙箱测试通过率和尝试次数。可使用学生和作业固定效应模型控制稳定的学生差异与题目差异，同时报告系数、置信区间和显著性。由于参与是自选择的，模型结果仍属于观察性关联。

目前的探索性结果没有发现稳定的成绩、通过率或尝试次数差异。正文应如实报告，并结合提交通过率天花板效应解释为何这些指标难以识别学习差异。

## 十一、伦理与表述边界

数据来自正常教学活动，研究分析在课程活动后进行，导出文件已删除直接身份信息，并使用匿名标识关联各表。

由于引导式学习参与与课程过程分存在联系，投稿前需要向学校伦理审查机构确认是否需要补充审查或取得豁免证明。论文说明研究分析不会追溯改变学生成绩。

全文遵守以下表述边界：

- 不将观察性关联写成因果效果；
- 不将带有成绩鼓励的使用写成完全自愿；
- 不把117个学生账户写成117名引导式学习参与者；
- 不把全部第二阶段称为 Parsons Problems；
- 不用代码提交高通过率证明学生真正掌握了算法；
- 不隐去采集期间的系统更新；
- 不把三个已有教学方法的简单并列宣称为全新理论。

中文研究稿应具备完整摘要、引言、相关研究、系统设计、方法、结果、讨论、局限和结论，并包含：

英文稿在中文稿事实和分析冻结后改写，不逐句直译。英文版根据目标期刊重新组织篇幅、研究贡献和相关研究。
