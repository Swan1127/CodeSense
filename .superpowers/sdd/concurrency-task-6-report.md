# Task 6 实施记录

日期：2026-07-22

## 完成内容

本任务补齐了并发评测的命令行入口、重复实验调度和论文输出。CLI 默认使用并发阶梯 `1,2,4,8,16,24,32`。平台模式首次运行限制在并发 8；只有显式传入 `--allow-validated-ramp` 才能继续提高并发，且任何模式都不能超过 32。

正式实验前按顺序执行 3 次预热。任一预热失败时，脚本会停止，不会进入正式阶梯，并把 `run_config.json` 标记为 `failed`。正式实验保留 3 个独立轮次及轮次编号，不把原始记录预先合并。混合负载按确定性规则分配；每档 20 个请求时为 12 个短请求和 8 个长请求。平台混合负载复用同一批已认证 Session，通过 `call_kind()` 选择短、长接口，不重复登录账号。

平台 canary 只加载本轮最大并发所需的凭据。例如并发上限为 8 时，只登录 8 个专用账号；完整阶梯才会使用 32 个账号。

输出包括：

- `raw_requests.jsonl`
- `level_summary.csv`
- `run_config.json`
- 三张 200 DPI PNG
- 按“轮次—并发档位”分开的资源采样 CSV

配置快照会递归删除密钥、密码、Cookie、Authorization、token 和 secret 类字段，并清除 URL 的用户信息、查询参数与片段。结果目录已有正式产物时默认拒绝覆盖。使用 `--overwrite` 时，只删除约定的产物和命名匹配的资源 CSV，不碰同目录中的其他文件。
